DiceBear-compatible avatar style

lexavataaars

Deterministic avatars for legal software — judges, prosecutors, notaries and advocates, in business formal and court dress. The same seed always renders the same person.

Built for products where a playful robot or a smiling cartoon would read as a mistake: case-law research, contract drafting, court filing, matter management. Every figure below was rendered by lexavataaars when this page was built.

npm: lexavataaars github MIT no runtime dependencies beyond @dicebear/core

Forty-eight seeds

Names in, avatars out. Nothing here was curated or retouched: this is createAvatar({ seed }) on an alphabet of ordinary practitioner names, in the order they are listed in the build script.

Install

bun add lexavataaars     # or: npm i lexavataaars
import { createAvatar } from 'lexavataaars'

const avatar = createAvatar({ seed: user.id })

avatar.toString()   // SVG markup
avatar.toDataUri()  // data:image/svg+xml,… for <img src>

@dicebear/core is the only dependency. Rendering is synchronous and does no I/O, so it works the same in a server render, a build step or the browser.

The wardrobe

Fourteen garments, thirteen of them drawn for this fork on the source's own shoulder and neckline geometry. Business formal outweighs court and academic dress roughly six to one, so a wall of these reads as a profession rather than as a costume department. Pin one with clothesVariant.

Options

The definition is a plain DiceBear style, so it takes DiceBear's render options — seed, size, scale, rotate, flip, borderRadius, backgroundColor, idRandomization — plus one option per colour group and one per component.

Colour groups

Each group below is an independent axis. Pass an array of hex values (without #) to restrict what the seed may choose from; pass one value to pin it outright. Splitting robe from facing, and shirt from accent, is what makes a house palette possible without touching the artwork.

OptionPalette
skinColor
Five tones, the source’s own range minus its two cartoon values.
hairColor
Eight values, constrained never to equal the skin beneath them.
facialHairColor
The hair list, adjusted where a beard sat on skin too close to it.
clothesColor
Suiting. Eight dark values — at 16px the torso is the style’s loudest statement.
robeColor
Court and academic dress. Three near-blacks so the gown is not flat.
facingColor
Silk facings on a gown, always lighter than the robe they sit on.
shirtColor
Linen, greyed on purpose so a white torso survives a white page.
accentColor
The one saturated note, on exactly one element at a time: the tie, the bow, the hood.
wigColor
Horsehair. Never taken from `hair`, or a third of the wigs come out ginger.
accessoriesColor
Spectacle frames: metal, horn, tortoise.
hatColor
The biretta. Cool darks only.

Gradients

Every colour group also exposes <name>ColorFill (solid, linear or radial), <name>ColorFillStops and <name>ColorAngle. They are DiceBear's, not this style's, and they are worth knowing about mainly because a house brand sometimes needs one.

createAvatar({
  seed: user.id,
  accentColor: ['7c2529'],
  accentColorFill: ['linear'],
  accentColorAngle: [45],
})

There is no notion of a role in this library, deliberately. A “judge” or a “notary” is something you compose in your own code out of the options above, and keep, because it is your product's decision rather than the library's.

const JUDGE = {
  clothesVariant: ['gown', 'gownAndBands'],
  robeColor: ['17171a'],
  facingColor: ['2a2a2e'],
} as const

const ADVOCATE = {
  clothesVariant: ['suit', 'suitAndWaistcoat', 'doubleBreastedSuit'],
  clothesColor: ['262e33', '2b3542'],
  accentColor: ['7c2529'],
} as const

createAvatar({ seed: user.id, ...JUDGE })

At the sizes it really appears

In a real product these turn up in a 16px table cell far more often than in a 128px profile card, so the artwork is tuned for the small end: the hair silhouette, the torso colour and the skin-to-cloth contrast are the only three things that survive down there, which is why the suiting palette is eight dark values and why the wig and the biretta earn their weight.

The same ladder with a background

The style has no background component — an avatar composites straight onto your surface, which is what lets it sit in a table row without a card around it. Below about 24px you generally want one anyway: a transparent figure on a busy or dark surface loses its edges. Pass backgroundColor (and borderRadius if you want it circular) rather than wrapping it in a div, so the shape travels with the SVG.

createAvatar({ seed: user.id, size: 16, backgroundColor: ['e8e3d9'], borderRadius: 50 })

DiceBear compatibility

The style is not a re-implementation of DiceBear — it is a DiceBear style. The whole thing is one JSON definition validated against @dicebear/schema, and it is exported so you can hand it to anything in that ecosystem:

import definition from 'lexavataaars/definition.json' with { type: 'json' }

That file works with DiceBear's CLI, their PNG and JPEG converters, their HTTP API when self-hosted, and their PHP, Python, Rust, Go and Dart ports — none of which this project has to maintain, and none of which need to know this style exists. The JavaScript wrapper published here adds nothing but a parsed Style instance and idRandomization on by default, which keeps two avatars on one page from sharing internal SVG ids.
